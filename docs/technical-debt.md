# Technical debt

Known limits we chose to ship with, each with the ceiling it puts on the product and the way out. Code carries the same notes as `ponytail:` comments (list them with `/ponytail-debt`). Keep this file in step: when a row is fixed, delete it and say so in `docs/BUILD_LOG.md`.

## AI system (PII masking, observability, RAG, MCP), added 2026-10-30

Design and stages: `docs/ai-rag-mcp-pii-plan.md`. Masking misses are measured by `python scripts/eval_pii.py --show` on 54 invented samples (`tests/fixtures/pii_eval.jsonl`); `tests/test_pii_eval.py` fails if any miss count goes up.

| # | Debt | What it limits | Way out | Where |
|---|---|---|---|---|
| 1 | Masking is regex plus the contact book. Measured misses: names not in the book or only partly written ("Zainuddin", "Zainuddin B.", a name of someone not a contact) 3 of 7; addresses 2 of 2; email written as "ali (at) shop dot my"; a phone with a letter O for zero; digits spoken as words; passport numbers; a bank account number with no bank or account word before it. Prices and document numbers are never altered (0 of 12) | What may reach the AI provider: any name or address not caught is sent. The version 2 notice says so | Address pattern (postcode plus state), first names of personal contacts, a passport pattern, a small local NER model if the miss rate matters | `src/parse_util.py` `Mask`, `scripts/eval_pii.py` |
| 2 | The model can change or drop a placeholder in its reply. An altered placeholder stays visible as text (for example `[NAME_9]`) | A reply can show a placeholder instead of the real name | Ask the model to copy placeholders verbatim and check the reply for unknown ones; retry once | `Mask.unmask` |
| 3 | The mask is rebuilt for every call, and every MCP response is masked on its own, so a client cannot match `[NAME_1]` across two calls or turn it back into a name | An AI tool sees stable text only inside one response | A per-session placeholder map, only if clients need it, with the same erase-on-close rule | `src/api/mcp.py` |
| 4 | A model call that fails and makes the route answer 502 (supplier document, enquiry) is rolled back with the request, so it is not in `ai_calls` | The AI activity table under-counts failures on those two routes | Write the row on a second connection after the rollback | `src/ai_log.py` |
| 5 | AI activity shows the last 100 calls with no filter by kind or person and no paging | An owner of a busy business cannot browse past 100 | Query parameters and paging on `GET /api/ai/activity` | `src/api/ai_activity.py`, `web/src/AiActivity.tsx` |
| 6 | Retrieval builds its text index on the fly over the NEWEST 2000 rows of each source. Older rows are not searched, silently | A business with more than 2000 quotes, contacts, catalog items, costs or supplier documents cannot find the oldest ones through the AI | A generated `tsvector` column with a GIN index per source, then remove the cap | `src/rag.py` `SCAN` |
| 7 | Retrieval uses the `simple` text-search configuration: no stemming, no Malay or Manglish word handling. Jobs and the activity feed are not sources | Plural, spelling and Malay variants miss; questions about jobs are not answered from records | Add a Malay dictionary or trigram matching; add jobs as a source with its own role check | `src/rag.py` |
| 8 | `ask` makes two model calls (pick the intent, then answer) and sends the masked question in both | Slower and dearer than one call | Pick the intent by rule for clear cases, or answer in one call | `src/api/assistant.py` |
| 9 | Nothing in the AI path has been run against a live model. Every test uses a fake transport. Answer quality, whether the model copies placeholders, and cost per question are unmeasured | We do not know how good `ask` is | Run it with a real ILMU key on a sample business and record accuracy in `docs/eval-manglish.md` | `docs/eval-manglish.md` |
| 10 | The version 2 notice (`RAG_DISCLOSURE`) has not been read by a lawyer. Consent is recorded per business, not per customer; the owner must put the AI use in their own privacy notice, and the app only tells them to | Compliance rests on the owner doing that and on the notice being sound | Legal review; a ready-made privacy-notice paragraph the owner can copy; a customer-facing notice in the chat | `src/api/ai_guide.py`, `docs/privacy-and-breach-runbook.md` |
| 11 | MCP has one tool (`search`) and is a thin JSON-RPC route: no streaming, no sessions, no SDK. Rate limit is 60 requests a minute per key, counted in memory per process | Fine for one worker. Several workers allow more than 60 a minute. Richer tools (a quote, stale costs, jobs) need their own role and masking review | Move the counter to the database or Redis; add tools one at a time with a test each; swap in the `mcp` SDK if a client needs streaming | `src/api/mcp.py`, `src/api/deps.py` `throttle` |
| 12 | An MCP key is bound to a role when it is made. There is no screen to change the role of an existing key; the way is revoke and create. Deleting the role switches its keys off with no message | Surprise when a role is deleted | Show "role deleted" on the key; allow changing the role | `src/api/public_api.py`, `web/src/ApiAccess.tsx` |
| 13 | None of the new screens (AI activity, the opt-in radio and notice, the AI tool key form, the Assistant's "hidden" and "not searched" lines) has been opened in a browser. The mock has no sample for the Assistant lines. The AI settings text is English and Malay only; the Assistant lines have four languages | Layout, phone width, keyboard and screen reader behaviour are unchecked | A click-through at desktop and phone width, with a screen reader pass; sample data in the mock; Chinese and Tamil for AI settings | `web/src/` |
| 14 | The owner's own AI server answers with `max_tokens` 400. A very long answer plus its cited ids could still be cut off, and the reply is then refused as not in the expected form | An occasional "could not read your records" message on a talkative model | Make it a setting, or ask for shorter answers | `src/api/ai_guide.py` `chat` |
