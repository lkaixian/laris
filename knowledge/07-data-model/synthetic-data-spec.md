# Synthetic data spec

Hackathon rule: synthetic data only. Everything is generated by one script `seed.py` with a fixed random seed, reading `config/templates/*.yaml`. Mark every seeded row `is_synthetic=true` (add column to `documents`, `parties`) and print "SYNTHETIC DATA" in the dashboard footer. No real names, phone numbers, SSM numbers, or real shop receipts. Schema: [[bidirectional-schema]]; flow: [[state-machines]].

## Volume per template (small on purpose)
| Item | Count |
|---|---|
| suppliers | 3 |
| customers | 4 |
| `in` documents | 6 (4 quotations, 2 receipts) incl. 1 older + 1 newer for the SAME item (price rise) |
| `in` receipt images | 2 per template, rendered as PNG from HTML (thermal-style narrow, one clean, one blurry/skewed) |
| `cost_items` | 10-15 |
| enquiry texts/voice | 4 (2 typed Manglish, 1 voice note, 1 photo of handwritten list) |
| `out` quotes | 4 across states: 1 draft, 1 sent, 1 read, 1 accepted->job |
| audit rows | produced by the seed running through real transitions, not inserted directly |

Seed by calling the same API/state machine the app uses, so audit_log and constraints are exercised.

## Mandatory scenario in every template (the "wow")
1. Supplier A quotation dated D-45 gives item X at price P0, accepted, in cost book.
2. Customer quote Q1 priced from P0, status `sent` (stale-able).
3. Supplier A re-quote dated D-3 gives item X at P1 > P0, accepted -> cost book.
4. `v_quote_bom.cost_is_stale = true` on Q1 -> alert "Q1 margin falls from m0 to m1". Numbers computed by the app, not hard-coded.
PLAN.txt warning: the rise must hit a MATERIAL-HEAVY job or the RM figure is trivial (3D print example moved only RM3.83). Choose templates where materials are at least 60% of cost, and set the seed price rise so the drop is visible; the exact rise % is a synthetic knob in the YAML (`demo_price_shock_pct`), label it as such.

## Template 1: made-to-order manufacturing (3D print / sign shop / custom fabrication)
- Items (`item_key`, uom): `pla_1kg`(kg), `petg_1kg`(kg), `acrylic_3mm_sheet`(sheet), `vinyl_roll`(m), `packaging_box`(pcs).
- Rate card: `machine_hour` (RM/h), `labour_hour`, in YAML as owner-entered values.
- Products: "bracket", "acrylic signboard 60x30", "name plate".
- Recipe example: bracket = grams (from STL volume x infill x density, OPTIONAL plugin; default uses `grams_per_unit` in enquiry) x filament cost + machine_hours x rate + packaging.
- Suppliers: 3 fake names ("Supplier A Filament Sdn Bhd" style, obviously fake). Receipts: filament + acrylic.
- Enquiries (Manglish): "boss nak 20 pcs bracket PLA hitam, bila boleh siap?"; voice note script (read into TTS or recorded by team) with same content; photo of handwritten list.
- STL: 1-2 trivial generated cubes/brackets via trimesh (no real customer files).

## Template 2: F&B / catering
- Items: `chicken_kg`(kg), `rice_25kg`(bag), `cooking_oil_5kg`(tin), `eggs_30`(tray), `disposable_box`(pcs), `gas_cylinder`(pcs).
- Rate card: `cook_labour_hour`, `delivery_flat` per trip.
- Products: "nasi lemak set per pax", "kuih box of 20", "buffet per pax (min 30)".
- Recipe: BOM per pax (qty of each ingredient per pax) x cost_items + labour + packaging. Margin guard floor higher variance, so seed a shock on `chicken_kg`.
- Supplier docs: wet market / wholesaler quotations (often a handwritten or WhatsApp price list photo, valid "this week" -> short `valid_until`, makes `expired` realistic). Receipts: 1 thermal-style, 1 handwritten.
- Enquiries: "nak order 50 pax nasi lemak untuk 12hb, ada halal cert?" (decoy: asking for something not in data -> `ask_clarification`), pax count + date + delivery address as `required_enquiry_fields`.

## Template 3: service / renovation
- Items: `paint_20l`(tin), `ceramic_tile_sqft`(sqft), `cement_50kg`(bag), `wire_100m`(roll), `skim_coat_sqft` (subcontract rate).
- Rate cards: `tiler_day`, `painter_day`, `electrician_day`.
- Products: "repaint room (per sqft)", "retile bathroom (per sqft)", "add 3 power points".
- Recipe: area x coverage_per_sqft (qty of material) x cost + days x rate + wastage_pct (in YAML) . Quote has long validity (30 days), site visit step as `required_enquiry_fields` ("photo of room").
- Supplier docs: hardware shop formal quotations (PDF-like PNG with item table), 1 with subtotals that don't add (OCR trap: arithmetic cross-check flags `needs_review`).
- Enquiries: photo of a room + voice note "cat 1 bilik 12x14 kaki, siling sekali".

## Messy-input fixtures (the AI part must be tested on these)
Per template: 1 clean, 1 hard. Hard = skew, blur, mixed BM/EN, handwritten digit ambiguity (1 vs 7), "kg"/"KG"/"kilo", missing unit, price with "RM" glued to number, total line mistaken for item. Store the expected parse JSON next to each image (`fixtures/<tpl>/<name>.expected.json`) so the OCR+LLM step has a pass/fail test. Report accuracy as measured on THESE fixtures only and say so.

## Users and roles
`owner` (1), `staff` (1). Staff login demonstrates margins hidden (same quote, two screens).

## Generation order
1. templates YAML 2. parties/users 3. render receipt/quotation PNGs (HTML->PNG; WeasyPrint is already in stack, PDF->PNG via pdf2image/pymupdf if installed, else screenshot) 4. run documents through the API to reach target states 5. enquiries via the Telegram bot test chat 6. assert `v_quote_bom` returns rows and exactly one stale quote per template.

## Rules
- Fake names carry "(demo)" in the name. Phone numbers: use obviously fake pattern. No scraped real prices.
- Placeholder prices are labelled `synthetic` and replaced when real Thursday data arrives; note replaced values in [[../08-validation/]].
- No external benefit claim (minutes saved, RM protected) may be quoted from synthetic data. Only Thursday's timed manual-vs-app run counts.
